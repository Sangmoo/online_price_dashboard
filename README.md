# ERP 영업 관리

영업 데이터 조회·관리용 로컬 웹 서비스입니다. 온라인몰 가격 수집 결과(`T_SELECT_ONLINE_MNG_R`) 분석과 매장 재고 실사계획(`T_SHOP_INVT_PLAN`) 관리를 제공합니다. React와 FastAPI로 만들었고, 대화형 분석에는 Claude API를 씁니다.

## 기능
| 화면 | 내용 |
|---|---|
| 로그인 | 사번과 사내 계정(`T_USR`) 비밀번호로 로그인. 비밀번호는 DB 안에서 `CRYPTO_DECRYPT(PWD)`로 비교하고, `USE_YN='Y'`이면서 삭제되지 않은 계정만 허용. **서비스 사용자 테이블(`T_ERP_WEB_USER`)에 등록된 사용자만** 들어갈 수 있음. 5회 연속 실패하면 1분간 잠금 |
| 세션 | 1시간 동안 사용하지 않으면 자동 로그아웃. API 호출이나 화면 클릭·입력이 있으면 1시간으로 다시 연장. 만료 5분 전에 경고와 연장 버튼 표시 |
| 대시보드 | 최대 31일 기간 선택. KPI, 추이, 분포, 사이트·**매장(매장코드)**·상품 순위 |
| 일자별 상세 | 컬럼 정렬, 통합 검색, 사이트·**할인율 범위**·**매장코드(여러 개, IN)** 필터, 매장코드·매장명 컬럼, **매장코드 채우기** 버튼(최근 7일, 판매처 매장 연결 권한 필요 · 전일자는 매일 02:00 `JOB_FILL_ONLINE_SHOP_ID` 자동), **표시 컬럼 선택**(사용자별 저장), **링크 복사**(현재 조건을 URL로 공유), 엑셀 다운로드 |
| AI 어시스턴트 | 우측 아래 💬 버튼. 이 서비스의 데이터(온라인 가격, 판매 현황·월별 매장별 판매 집계, 매장 재고 실사계획)만 조회해서 답변하고, 그 외 주제는 거절. **사용자의 메뉴 권한이 있는 데이터의 조회 도구만 제공**되며 서버에서도 한 번 더 권한을 검사. **대화 기록은 사용자별로 저장**되고 다시 열어 이어갈 수 있음. **즐겨찾는 질문** 저장, 결과 표를 **차트로 전환**하거나 엑셀로 저장. AI 에게 일부만 보인 표(행 수 제한)는 **[전체 N행 엑셀]** 로 같은 조건의 전체 결과(최대 10만 행)를 다시 조회해 받음. 오늘 사용량(질문 수·비용) 표시 |
| 판매 분석 › 판매 현황 | 기간(기본 최근 마감 월, 최대 12개월)·**비교 기준**(전년 동기 / 직전 기간 / 직접 선택)·**브랜드** 조건으로 [조회]. 실판금액과 비교·보조 비교(전월 또는 전년 동기) 증감, **목표 달성률**(`T_SHOP_SELL_MGOAL`), 연 누계·수량·원가율·할인금액·판매 매장, 최근 13개월 추이(전년 같은 달·원가율), 브랜드별(목표·달성률), 매장 순위(매출 상위·목표 달성률 하위·성장·하락, 폐점 제외). 매장을 누르면 12개월 추이. **할인율**(할인금액 ÷ (실판금액 + 할인금액)). 아래에 **판매형태 구성**(행사/정상/세일 등 비중·비교 기간 대비·월별 비중), **상품 순위**(기간 안 순위, 실판금액·수량·할인율), **아이템·품군별 비교 기간 대비**. **보고용 엑셀**(요약·월별 추이·브랜드별·팀별·상품·판매형태·매장 순위·전체 매장, 요약 시트에 월별 추이·브랜드별 엑셀 차트). 월×매장 사전 집계 뷰로 즉시 표시 |
| 판매 분석 › 월별 매장별 판매 집계 | `T_CLOSE_SALE_BASE`(마감 매출 기초 데이터) 조회. 판매년월 FROM~TO(최대 36개월), 매장코드(팝업에서 여러 개 선택), 기획년도·시즌(여러 개 선택) 조건. `판매년월, 매장코드` 순 정렬, 100건씩 페이징, 건수·수량·실판금액·할인금액 합계. 엑셀은 조회 조건의 전체 결과를 건수 제한 없이 내려받음. 서버가 백그라운드로 만들고(진행률·남은 시간 표시, 다른 메뉴로 가도 계속), 100만 행마다 다음 시트에 이어서 담음. 완료 파일은 2시간 동안 다시 받기 가능. **요약 · 전년 비교** 탭: 월·매장·기획년도·시즌·품군별 수량·실판금액·할인금액·비중·원가 금액·원가율과 전년 동기 대비 증감(기간 12개월, 기획년도 1년 앞당긴 같은 조건), 추이/상위 차트, 엑셀. 매장을 누르면 최근 12개월 판매 추이 |
| 데이터 관리 › 매장 재고 실사계획 | `T_SHOP_INVT_PLAN` 등록·수정·삭제(소프트 삭제). 매장코드 팝업에서 매장을 고르면 브랜드·유통·매장명·전년/당년 매출·최종실사일·관리등급(`T_SHOP_INVT_RANK`)·재고·매장번호가 자동으로 채워지고, 조회되지 않은 항목은 "데이터 없음"으로 표시해 수기 입력. 매니저 팝업(`T_SHOP_SMAS`), 실사예정일 셀 더블클릭으로 날짜 지정(비우면 미정), 2단 헤더 엑셀. 매장코드(또는 📈 버튼)를 누르면 그 매장의 최근 12개월 판매 추이·전년 비교 |
| 관리자 (ADMIN만 표시) | 사용자별 권한(ADMIN/USER), AI 사용 여부, 일일 한도, 계정 사용 중지 관리. **메뉴 권한** 탭(사용자×메뉴 표에서 일괄 부여·회수 후 저장, 사용자 목록의 [설정] 팝업). **AI 도구** 탭(사전 집계 뷰 상태·[지금 갱신], 기본 도구 사용/중지·설명 수정·추가 안내, 조회 SQL 로 관리자 정의 도구 추가·수정·삭제·시험 실행). **변경 이력** 탭(사용자·메뉴 권한·AI 설정·AI 도구 변경, 잠금 해제, 강제 로그아웃의 변경 전/후). 전역 AI 설정(기본 한도, 모델, effort), AI 사용 현황, 로그인 기록·잠금 해제, 접속 세션 강제 로그아웃, **설정 백업**(사용자·권한·전역 설정·AI 도구를 JSON 파일로 받고, 복원 전 바뀌는 내용 미리보기 후 선택 항목만 복원), **문의·신고**(사용자가 화면 오른쪽 위 [문의·신고]로 남긴 오류·요청·문의와 자동 첨부된 화면·조회 조건·최근 오류, 상태·답변 관리), **메뉴 이용**(최근 7·30·90일 메뉴별 열람 횟수·이용자·이용률, 사용자×메뉴 표에서 권한은 있지만 안 쓰는 메뉴 표시), **서버 상태**(최근 1·7·30일 가동 시간·자동 재시작·요청/응답 시간·느린 요청·느린 SQL 상위·오류·DB 연결·디스크, 로그 보관 기간 설정), **서버 로그**(요청·느린 쿼리·SQL 오류·엑셀 작업·로그인·AI 기록 조회). 원본에 사전 집계 뷰보다 새로운 마감 월이 들어오면 관리자 화면 상단에 **갱신 알림** |

### 판매처 매장 연결 (온라인 가격 › 판매처 매장 연결, 메뉴 권한 `mall_shop`)
- 가격 수집의 사이트(MALL_NM) · 판매자번호(NAVER_PAY_SELL_NO) · 브랜드(품번 첫 글자 S/T/A, `*` = 공통)마다 매장코드를 연결합니다.
  수집 프로그램은 이 연결(`T_SELECT_ONLINE_MALL_SHOP`, `db/create_online_mall_shop.sql`)로 `T_SELECT_ONLINE_MNG_R.SHOP_ID` 를 채웁니다
  (브랜드 행 → 없으면 `*` 행, 판매자번호가 없으면 `-`).
- 화면(기본 최근 7일, [조회]로 반영): 판매자번호가 있는 수집 조합만, 사이트 → 판매자번호 → 브랜드 순. 수집 행·상품 수·연결 매장·수집 테이블 반영률,
  매장정보 예시(판매자번호마다 같은 RMK 가 절반 이상일 때, 모델번호 부분 제외), 같은 브랜드 매장 후보(매장정보 예시 → 사이트명 순, 체인·지역 순서 무관),
  [후보 채우기], 변경분만 저장(매장코드는 T_SHOP 확인, 변경 이력 기록). 매장코드를 비우고 저장하면 연결 해제.
- AI: `search_mall_shop_mappings`(조회), `propose_mall_shop_mappings`(변경안 — **저장하지 않음**, 대화창의 [적용] 카드를 사용자가 눌러야
  화면과 같은 권한·검증·변경 이력으로 저장).

### 시즌 판매 진척 · 온라인 할인 주의 상품 (판매 현황)
- **시즌 판매 진척**: 시즌(기획년도+시즌)별 월 누적 판매를 전년 같은 시즌의 같은 시점(12개월 전 같은 달)과 비교하고, 전년 시즌 최종 누적 대비 진척률을 보여줍니다.
  기본 시즌은 기준 월에 가장 많이 팔린 시즌. 상품 사전 집계 뷰가 있으면 즉시, 없으면 원본에서 10초 안팎(10분 캐시).
- **온라인 할인 주의 상품**(온라인 가격 메뉴 권한도 있는 사용자): 판매 현황 조건의 매장 실판금액 상위 50개 상품 중 온라인 최근 7일 평균 할인율이
  그 전 4주보다 3%p 이상 오른 상품(또는 새로 15% 이상 할인된 상품).
- **세일 비중이 높은 매장**: 매장 실판금액 중 세일 판매(판매형태에 '세일') 비중이 같은 브랜드 전체 비중보다 크게 높은 매장 상위 15개
  (월평균 1천만원 이상·폐점 제외, 행사·특판 전용 매장은 선택 시 포함), 비교 기간 대비 변화.
- 시즌 판매 진척은 [아이템별 보기]로 아이템마다 누적·전년 같은 시점·진척률을 볼 수 있습니다.
- **첫 화면 미리 계산**: 기본 조건(최신 월·전년 동기)의 판매 현황·상품 패널·시즌 진척을 사용자 브랜드 권한 조합마다 [지금 갱신] 직후, 서버 시작 시,
  매일 아침 7시에 미리 계산해 둡니다. 30분마다 데이터 상태를 확인해 바뀌었으면 다시 계산합니다 (관리자 › AI 도구 › 사전 집계 뷰에 마지막 계산 시각).

### 문의 · 오류 신고
- 화면 오른쪽 위 [문의·신고]: 오류/요청/문의를 남기면(최대 1만 자) 현재 화면·조회 조건·최근 요청 오류가 자동으로 함께 저장되고, 같은 창의 '내 문의'에서 답변을 봅니다.
- 새 답변이 달리면 [문의·신고] 버튼에, 관리자에게는 사이드바·탭에 미처리 건수가 표시됩니다 (5분마다 확인, 세션 연장 없음).
- 완료된 문의의 첨부 이미지는 관리자가 정한 기간(기본 12개월, 0 = 계속)이 지나면 정리 작업이 지웁니다 (글·답변은 남김).
- 이미지 최대 3개(PNG·JPG·GIF·WEBP, 각 5MB) 첨부: 파일 선택·끌어놓기·캡처 붙여넣기(Ctrl+V). 형식은 파일 내용으로 확인하고, 작성자 본인과 관리자만 볼 수 있습니다.
- 저장소 `T_ERP_WEB_FEEDBACK` + `T_ERP_WEB_FEEDBACK_FILE`(`db/create_erp_web_feedback.sql`, 기존 테이블은 `db/alter_erp_web_feedback_files.sql`). 두 테이블이 없으면 서버 로컬 SQLite 에 저장하고, 만들면 1분 안에 옮깁니다.

### AI 분석 도구 (판매 현황 화면과 같은 계산)
- `get_season_progress`: 시즌 판매 진척 (판매 메뉴) · `find_online_discount_alerts`: 온라인 할인 주의 상품 (판매 + 온라인 가격 메뉴)
- `get_product_insight`: 품번 하나의 온라인 가격·매장 판매·많이 팔린 매장·같은 아이템 순위 (권한 있는 쪽만)
- `aggregate_sales` 는 매장 조건·묶음 없이 기획년도·시즌·품군·아이템·판매형태·상품 단위면 상품 사전 집계 뷰에서 같은 합계를 계산합니다 (약 8초 → 0.4초).
- 관리자 › AI 사용 현황 › 도구별 사용: 서버 로그 기준 도구별 호출·입력 오류·조회 실패·응답 시간, 모델 선택·전환 횟수, 쓰이지 않은 도구.

### 상품 팝업 (온라인 가격 ↔ 매장 판매)
- 온라인 가격 대시보드·일자별 상세의 품번, 판매 현황 상품 순위의 품번을 누르면 같은 품번의 **온라인 가격(최근 31일 평균 할인율·최저가·사이트별 가격)**과
  **매장 판매(최근 12개월 수량·실판금액·할인율)**, **많이 팔린 매장·팀(최근 3개월)**, **같은 브랜드·기획년도·시즌·아이템 품번 사이 순위**를 함께 보여줍니다. 온라인 가격 메뉴 권한이면 온라인 쪽, 판매 메뉴 권한이면 매장 쪽이 보입니다.
- 상품 단위 판매는 상품 사전 집계 뷰 `MV_CLOSE_SALE_PRDT_YM`(`db/create_mv_close_sale_prdt_ym.sql`, [지금 갱신]이 함께 갱신)를 씁니다.
  뷰가 없으면 판매 현황의 상품·판매형태는 기간 1개월일 때만, 상품 팝업은 최근 6개월만 원본에서 계산합니다.

### AI 모델 자동 선택 (관리자 › AI 사용 설정, 기본 꺼짐)
- 값·목록을 바로 묻는 짧은 질문은 단순 조회용 모델(기본 Haiku 4.5, effort low), 분석·원인·비교·제안 질문과 애매한 질문은 기본 모델로 답합니다.
- 단순 조회 모델이 도구 입력을 2번 틀리거나 요청을 거부하면 그 질문은 기본 모델로 넘깁니다. AI 사용 현황에 모델별 호출·비용을 표시합니다.
- AI 답변의 도구 표시를 누르면 실제 조회 조건(답변 근거)을 볼 수 있습니다.

### 매장 정보 팝업 · 담당 영업직원
- 판매 현황 · 판매 요약 · 재고 실사계획에서 매장(코드)을 누르면 **매장 정보** 팝업: 브랜드·팀·담당 영업직원(사번·이름)·운영상태·오픈/폐점일·주소·전화,
  최근 12개월 판매(전년 비교)와 **월별 목표·달성률**, 실사계획 권한이 있으면 실사 일정·현재 매니저.
- 매장·담당 영업직원은 ERP 의 `T_SHOP_BRD`(회사 A01C01) + `T_SHOP`(팀명 `T_COMN_CD`, 직원명 `T_EMP`, 운영상태 `F_GET_NM_CLSBY`) 기준, 10분 캐시.
- AI 도구 `search_shops`: 매장 담당자, 영업직원별 담당 매장·매장 수, 팀/브랜드/운영상태별 매장 (판매·실사계획 메뉴 권한, 기본 영업 중 매장만).
- 브랜드 권한이 제한된 사용자는 허용 브랜드 매장만 봅니다 (실사계획 화면에서 연 매장 정보는 거르지 않음, 목표는 허용 브랜드만).

### 브랜드별 데이터 권한
- 사용자마다 볼 수 있는 브랜드(쉬즈미스·리스트·시스티나)를 정합니다. **모든 브랜드**(기본, 기존 사용자 전원) 또는 브랜드를 골라 제한합니다.
- 관리자 › 사용자 · 권한에서 사용자 추가 시 반드시 선택하고, 목록의 [설정]으로 바꿉니다. 최고 관리자는 항상 모든 브랜드입니다.
- 서버에서 거릅니다: 판매 현황(선택지·숫자·비중·보고용 엑셀), 월별 매장별 판매 집계(조회·요약·할인 합계·전체 엑셀·매장 추이·매장 선택 팝업), AI 판매 도구.
  관리자 정의 AI 도구 중 판매 메뉴에 연결된 것은 SQL 을 거를 수 없어 브랜드가 제한된 사용자에게 주지 않습니다.
  온라인 가격·매장 재고 실사계획은 브랜드 제한 대상이 아닙니다.
- 사전 집계 뷰가 최신이면 허용 팀에서 팔린 매장코드로 바꿔 조회해 느려지지 않습니다 (결과는 팀 조건과 같음, 다른 팀으로도 팔린 매장이 있으면 팀 조건을 함께 검).
- 저장: `T_ERP_WEB_USER_BRAND`(`db/create_erp_web_user_brand.sql`, 행 없음 = 모든 브랜드). 테이블을 만들기 전에는 모두 모든 브랜드로 동작합니다.

### 판매 현황의 목표 대비
- 목표는 `T_SHOP_SELL_MGOAL`(매장 × 브랜드 × 월 목표금액, `DEL_DAY` 없는 행)을 **매장 단위로 합쳐** 씁니다.
- 판매는 매장의 팀(`TEAM_CD`, 예: 쉬즈3팀 → 쉬즈미스, 리스트1팀 → 리스트) 하나로 잡히므로, 한 매장에 여러 브랜드 목표가 있어도 목표를 그 매장의 **판매 브랜드**로 모읍니다.
  그래서 브랜드별 목표금액은 ERP 의 브랜드코드(`PARENT_BRD_CD`)별 합계와 다를 수 있습니다 (전체 합계는 같음). 판매가 없는 목표 매장은 목표 브랜드코드로 분류합니다.
- 달성률 = 목표가 있는 매장의 실판금액 ÷ 목표금액. 목표가 없는 매장의 매출은 따로 표시합니다.

### AI 도구 관리
- 기본 도구 10개(온라인 가격 3, 판매 현황 1, 판매 집계 3, 실사계획 2, 매장 정보 1)는 조회 방식이 코드에 고정되어 있고, 관리자는 사용/중지, AI 에게 주는 설명(기본값으로 되돌리기 가능), 추가 안내를 바꿀 수 있습니다.
- 관리자 정의 도구는 `SELECT`/`WITH` 한 문장과 `:이름` 파라미터로 만듭니다. 파라미터 형식(문자열·정수·숫자·날짜·년월·선택값)을 검사한 뒤 바인드로만 전달합니다.
- 쓰기·DDL·PL/SQL·`DBMS_`/`UTL_` 패키지·DB 링크·`FOR UPDATE`·비밀번호 복호화(`CRYPTO_*`, `PWD`)·주석은 저장 단계에서 거부하고, 실행은 읽기 전용 트랜잭션 + 30초 제한 + 최대 행 수 제한으로 합니다.
- 도구마다 메뉴를 연결하고, 그 메뉴 권한이 있는 사용자에게만 AI 가 제공·실행합니다.
- 설정은 `T_ERP_WEB_AI_TOOL`(`db/create_erp_web_ai_tool.sql`)에 저장합니다. 테이블이 없으면 서버 로컬에 저장하고, 테이블을 만들면 자동으로 옮깁니다.

### 권한과 한도
- `250016`(`SUPER_ADMIN_ID`)은 항상 ADMIN이며, 권한을 바꾸거나 비활성화할 수 없습니다. 사용자 테이블에 없으면 첫 로그인 때 ADMIN으로 등록됩니다.
- 그 외 사용자는 자동 등록되지 않습니다. 관리자가 **사용자 추가**에서 사번을 검색해 등록하고, 이때 권한·메뉴 권한·AI 사용 여부·일일 한도를 함께 지정합니다.
- 사용자 ID는 사번(6자리 숫자)이어야 하고, `T_USR`에 사용 중인 계정으로 있어야 등록됩니다.
- AI 기본 한도는 사용자당 하루 **질문 10회, 비용 $2.00**입니다. 관리자 화면에서 기본값을 바꾸거나 사용자별로 따로 지정할 수 있습니다.
- 비용은 응답 토큰 사용량(입력·출력·캐시)에 모델 단가를 곱해 계산합니다. 답변 도중 한도에 도달하면 그 자리에서 중단합니다.
- 서버 오류로 답변을 전혀 받지 못한 질문은 질문 수에서 빼 줍니다.
- 페이지 권한은 서버 API에서도 검사하므로, 화면에서 메뉴만 숨기는 방식이 아닙니다.

## 실행 (로컬 배포)
1. `.env.example`을 복사해 `.env`를 만들고 DB 정보와 `ANTHROPIC_API_KEY`를 입력합니다.
2. 처음 한 번만 `setup.bat`를 실행합니다. Python 가상환경을 만들고 패키지를 설치한 뒤 프론트엔드를 빌드합니다.
3. `start.bat`를 실행하면 http://localhost:8000 에서 API와 화면이 함께 서비스됩니다.

개발 중에는 `dev.bat`를 실행합니다. 백엔드는 8000번(자동 재시작), 프론트는 5173번(HMR)에서 뜹니다.

### 변경 반영 (deploy.bat)
코드를 받은 뒤 `deploy.bat` 만 실행하면 됩니다 (관리자 권한 불필요). 서버 테스트 → 화면 테스트 → 화면 빌드 → 서버 재시작 → 새 서버 기동 확인 순서로 진행하고,
중간에 실패하면 서버는 그대로 두고 멈춥니다. `deploy.bat quick` 은 테스트를 건너뜁니다.
- 백그라운드 서비스로 실행 중이면 `backend/data/service.restart` 파일로 감시 실행기에 서버 재시작만 요청합니다 (몇 초간 접속 끊김).
- `start.bat` 창으로 실행 중이면 그 창을 다시 실행하라고 안내합니다.
- 감시 실행기(`service.py`) 자체가 바뀐 경우에만 `service_stop.bat` → `service_start.bat`(관리자 권한)을 한 번 실행합니다.
- 배포 뒤 이미 열려 있던 화면에서 메뉴를 열면 새 화면 파일을 받도록 한 번 자동 새로고침합니다.

### 백그라운드 서비스로 실행 (권장)
창 없이 PC 시작 시 자동 실행되고, 서버가 꺼지거나 멈추면(30초마다 확인, 3번 연속 응답 없음) 자동으로 다시 띄웁니다.
- `service_install.bat` (관리자 권한으로 실행): 작업 스케줄러에 `ERP_Sales_Web` 을 SYSTEM 계정·PC 시작 시 실행으로 등록하고 바로 시작
- `service_status.bat`: 등록 상태·서버 응답·최근 감시 기록 / `service_stop.bat`, `service_start.bat`: 중지·시작 / `service_uninstall.bat`: 제거
- 기록: `backend/logs/service.log`(감시), `backend/logs/server-console.log`(서버 출력). 서비스가 실행 중이면 `start.bat` 은 브라우저만 엽니다.

서비스 데이터 저장 위치:
- **Oracle** (재배포해도 유지): 사용자 권한·메뉴 권한·AI 한도(`T_ERP_WEB_USER`, `T_ERP_WEB_USER_PAGE`), 전역 설정(`T_ERP_WEB_SETTING`), AI 사용량(`T_ERP_WEB_AI_USAGE`, 테이블이 있을 때 자동 사용). DDL은 `db/` 폴더에 있습니다.
- **Oracle** 운영 데이터: 로그인 세션(토큰은 SHA-256 해시로만 저장), 로그인 잠금·기록, AI 대화 기록, 즐겨찾기, 개인 화면 설정 (`db/create_erp_web_session.sql`), AI 도구 설정(`T_ERP_WEB_AI_TOOL`), 관리자 변경 이력(`T_ERP_WEB_ADMIN_LOG`, `db/create_erp_web_admin_log.sql`).
  테이블이 없는 환경(다른 PC·테스트)에서는 `backend/data/app.db`(SQLite, git 제외)를 쓰고, 테이블이 생기면 한 번 옮깁니다.
- 판매 집계 속도 개선용 인덱스 DDL: `db/create_ix_close_sale_base_04.sql`
- 브랜드 권한 `db/create_erp_web_user_brand.sql`, 메뉴 이용 기록 `db/create_erp_web_menu_usage.sql` (테이블이 없으면 서버 로컬 기록 후 생기면 옮김)
- 온라인 가격 수집 테이블 공간 정리·인덱스 **제안**(자동 실행 안 함): `db/suggest_online_mng_index.sql`
- 상품 사전 집계 뷰 `SS10.MV_CLOSE_SALE_PRDT_YM` (`db/create_mv_close_sale_prdt_ym.sql`, 수동 갱신 — 있으면 [지금 갱신]이 함께 갱신)
- 월×매장 사전 집계 뷰 `SS10.MV_CLOSE_SALE_SHOP_YM` (수동 갱신): AI 도구 `sum_sales_shop_month`(월별·매장별·팀별 단순 합계)가 사용합니다.
  뷰가 최신이 아니거나(STALE) 요청 기간의 최근 월이 아직 뷰에 없으면 같은 합계를 원본 테이블에서 계산합니다.
  전월 마감 적재가 끝나면 관리자가 **관리자 › AI 도구 › 사전 집계 뷰 [지금 갱신]** 으로 갱신합니다 (원자적 갱신 — 끝날 때까지 이전 데이터로 조회, 끝나면 캐시를 비워 즉시 반영, 변경 이력에 기록).
  원가 금액(제조원가×수량)은 뷰에 `TOTAL_COST_AMT` 가 있어야 뷰에서 읽습니다 (`db/create_mv_close_sale_shop_ym.sql`). 없으면 원본에서 정확히 계산합니다.

## 운영 로그
`backend/logs/` (git 제외, 매일 자정 날짜별 파일로 교체: `app.log.2026-09-29`)
- `app.log`: API 요청 1건당 1줄(사용자·경로·상태·소요시간), 느린 쿼리(기본 3초 이상, `SLOW_SQL_SEC`), 엑셀 작업 시작/완료, 로그인 성공/실패, AI 질문·도구 호출·비용
- `error.log`: 오류만 (스택 포함)
- 비밀번호·세션 토큰·SQL 바인드 값은 기록하지 않습니다. 관리자 화면 › 서버 로그에서도 조회할 수 있습니다.
- 보관 기간(기본 **7일**, 관리자 화면 › 서버 상태에서 변경)이 지난 날짜 파일은 6시간마다 자동 삭제하고, 로그 폴더가 1GB 를 넘으면 오래된 것부터 지웁니다.
  관리자 변경 이력·로그인 기록·AI 사용 기록(DB)은 지우지 않습니다.

## 테스트
처음 한 번 `backend\.venv\Scripts\python -m pip install -r backend\requirements-dev.txt` 후
- `test.bat` : 전체 (Oracle 에 접속되면 통합 테스트까지, 조회만 하며 데이터는 바꾸지 않음)

- `test.bat e2e` : 화면 테스트 (Playwright, PC 의 Edge 사용, 약 30초). 서버 API 를 가짜 응답으로 대신해 실제 서버·DB·계정에 접속하지 않습니다.
  처음 한 번 `frontend` 폴더에서 `npm install`. 로그인·메뉴 권한·판매 현황 조건/엑셀·판매 집계 자동 조회·관리자 알림·서버 상태를 확인합니다.

단위 테스트는 로그인·잠금·미등록 사용자 차단·세션 만료·페이지 권한, 관리자 입력 검증, AI 도구 권한과 입력 검증,
판매 집계 조건 검증·월 단위 페이징·전년 비교, 판매 현황 기간·비교 기준·목표 배분·브랜드 조건·보고용 엑셀, 대용량 엑셀 시트 분할·특수문자,
실사계획 입력 검증, 비용 계산, 로그 조회·보관 정리·서버 상태 요약, AI 표 전체 엑셀의 행 수 상한·권한을 확인합니다.
통합 테스트는 실제 데이터로 페이징 결과가 전체 정렬 결과와 같은지, 요약 합계가 직접 합계와 같은지, API 권한 등을 확인합니다.
